## Design and contracts
One shared Go helper, placed in existing `internal/templates/connections.go` and exported for the already-dependent database package, computes SHA-256 of exact session name bytes as 64 lowercase hex, without normalization, trimming or URL/driver. A namespaced version belongs in the storage key; header and attribute contain the same plain digest. Go's decoded session JSON map keys are the common source; hash even the empty string when it is an actual map member. This deterministic pseudonym is non-secret but guessable, not encryption. No JS digest or secure-context API needed; works under remote HTTP. Name reuse shares history, as it shares session identity.

Selector renderer adds `data-query-history-id="<digest>"` to each actual map-member option, including empty-name member. Omit it for no-connections placeholder and synthetic missing-current first option; determine membership using Go map comma-ok, not nonempty name, text, value or label. Escape option name as HTML text so entity-like and markup-bearing names cannot alter option structure; escape the corresponding tree name text too, to prevent injection or malformed OOB markup. Preserve ordering, selected choice, placeholder and existing form value/URL semantics, including same-URL switching; do not use the digest as selector value or change connection handling. Since HTML text encoding can alter unsafe names' prior accidental interpretation, this is the minimal necessary correction for faithful selector rendering, not a new selector policy. Do not parse or copy option text for identity. Existing URL-bearing option value is not history metadata. If safely preserving existing value semantics for arbitrary URL/driver requires broader changes, stop for replan rather than silently changing selection.

In `QueryCurrent`, resolve current name, URL and driver once from the same decoded request-session snapshot. When current is a string and an actual map member, including empty-name member, set `X-Query-History-Connection: <digest>` before body, including empty-query and SQL-error HTML. Missing member, absent current or malformed session gets no header; preserve preexisting lookup, execution, status/body/content type and logging behavior otherwise; no session mutation, endpoint or extra SQL. Do not alter other callers of `getConnection`; use narrowly scoped resolver as needed. Header/attribute share exactly the same helper, never expose URL, driver, credentials, SQL or results. Existing app already serves selector over same origin; no new credentials or history leave browser.

Capture exact submitted `sql`, timestamp and submission sequence at HTMX request start, keyed by actual XHR, only for real query POST initiators. On completion use only that XHR's valid response header to append once, including accessible SQL/HTTP errors; ignore missing/invalid header, network loss, timeout or abort, clean transient state, never retry or infer identity. Preserve query submission if history code throws. Response order cannot misattribute SQL. Sort by request timestamp and per-tab in-memory sequence before trim to 50; duplicate entries stay separate. Reload ties may retain array order. Pending response after deletion/clear is a later add; never resurrect already deleted entries from stale snapshots.

Display uses the valid data attribute on the selected option actually present, never text/value. Initial load and selector swaps recompute; hide/unavailable during switch until actual returned selector confirms. On stale, failed or overlapping swaps and creation, recompute after each actual DOM swap; asynchronous rendering must match current identifier/generation. Other tab can change shared cookie while selector appears stale: display follows this tab's DOM; query recording follows its response ID, not stale selection. Refresh visible list on storage events; no synchronization request. For missing/synthetic option do not display a list. Any real but unexpectedly stale option is harmless; a response without valid identity is not stored.

Persist namespaced versioned per-digest key, JSON array of `{sql,timestamp}` only. Validate shape, strings and dates, bound arrays; serialize local mutations and reread before each. Cross-tab localStorage read-modify-write has no atomicity: simultaneous tabs can lose additions/deletes/clear, although every successful write stays capped and isolated. Guard getter/get/set/remove and parsing, plus initial and toggle theme storage access; errors cannot cancel query, history may be unavailable. Never remove unrelated keys.

Render SQL using `textContent`, with preview, accessible full text, readable time and load/remove controls; show sensitive local storage warning. Panel outside `#query-main` survives editor swaps. To prevent history actions firing pending delayed Auto-Run, suppress only already scheduled auto input at `htmx:beforeRequest` using editor/generation marker invalidated by later genuine input; never dispatch input on load, or cancel manual/tree-generated requests. Real HTMX verification is mandatory. In-flight query cannot be undone. Provide accessible names, keyboard, visible focus, both themes and 320px layout.

Alternatives rejected: hashing selected text fails entity/whitespace names; JavaScript SHA adds unnecessary code; URL identifier leaks metadata; selector-based request attribution fails races; suspending recording loses submissions; secure-context-only Web Crypto fails HTTP; server history/new endpoint unauthorized. Shared server digest unifies exact identities while minimizing code and avoiding asynchronous client hashing.
