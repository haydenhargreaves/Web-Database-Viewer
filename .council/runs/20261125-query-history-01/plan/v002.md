## Design and contracts
Place a permanent labelled history section after `#query-main`. Use plain DOM elements and existing Tailwind classes; dynamic SQL via textContent, never HTML; buttons `type=button`, accessible names and visible focus. Expose full SQL via selection and an accessible full-text display or equivalent; preserve multiline. Announce browser-local sensitive storage and provide clear. Use a delegated query-request lifecycle hook, narrowly filtering the actual POST `/v1/api/query` and editor/manual initiators, so one record corresponds to each outgoing request, not input or response. Capture the submitted `sql` from HTMX request parameters at request time; no de-duplication, trim only to test emptiness, and do not cancel requests on storage exceptions. Submission failure still records. Protect malformed entry structures, dates and storage methods with try/catch; never overwrite unrelated localStorage keys. If read/write fails show an unobtrusive unavailable state; continue execution.

Use selected option text as the name (not its URL-bearing value); generate a SHA-256 digest from the exact UTF-8 name via Web Crypto in secure contexts, store under a namespaced key with digest, and only `{sql, timestamp}` in an array newest-first. Treat an empty selector/placeholder as no selection without inspecting or persisting its URL; use option presence and server output's placeholder shape. Cryptographic digest is pseudonymization, not a secrecy guarantee; names are user-provided so no connection name, URL, driver or other connection details appear verbatim in keys/values. Hashing must fail closed for history, not for query execution, if Web Crypto is unavailable. Cache computed identity and serialize per-connection asynchronous updates to preserve every rapid submission and ordering. Capture name and submitted SQL synchronously at request time, and bind async operations to that snapshot; never apply stale rendered lists after selector changes. On selector `change`, avoid recording against a transient selection before server confirms replacement: suspend history association during connection POST until replacement; on after-swap derive actual selected name and refresh; on error restore/refresh from confirmed selection or make history unavailable, never assign the wrong connection. Listen to HTMX swaps for creation, initial load, manager close and toggle; avoid relying on listeners attached to replaced elements. If server selects a different name for duplicated URLs, response selection is authoritative. This preserves backend wire contract.

Pending delayed inputs: history selection, removal and clear must not lead to execution of an earlier scheduled Auto-Run. Guard the next pending auto request after a history action using a per-current-editor generation/dirty marker, cancelling that stale request at HTMX `beforeRequest`, without emitting input or interfering with new genuine input; new input invalidates the stale marker and HTMX's debounce replaces its timer. In-flight requests already sent cannot be unsent; never cancel an unrelated manual request. Verify exact behavior with actual HTMX, including timing and later genuine input. If HTMX lifecycle cannot distinguish stale request reliably, use a narrowly scoped alternative verified with actual version and preserve tree input semantics; materially changing query execution elsewhere requires replan. Choosing a naive assignment-only handler fails on an already pending timer; replacing HTMX or moving history server-side is unnecessarily invasive.

## Edge cases, security, compatibility
Render untrusted SQL as text (including `<img onerror>`), never interpolate HTML or selectors. Storage entries must be validated: array of objects with string SQL and valid timestamp; ignore invalid records and bound output, never throw. Test absent/malformed JSON, non-array, invalid entries, denied getter/getItem/setItem/removeItem and quota, including theme behavior. Avoid logging SQL or connection values. No background requests or history data sent to any endpoint. Name digest is not encryption; browser profile users can read SQL. Test no connection, empty whitespace, unicode/multiline and huge SQL, duplicate entries, URL-like names, rapid actions and invalid timestamps. Async hash/write must not reorder or leak histories after switches. Clearing/removal must not affect another connection or unrelated localStorage; serial queue prevents a pending add resurrecting deleted data. In-flight cross-tab writes are not atomic; last writer may win. Page reload and request races should be tested; true server switch failure must not label a query with an unconfirmed name. A changed connection name can reuse or lose history; not a new identifier policy. No migrations, transactions or server changes.
