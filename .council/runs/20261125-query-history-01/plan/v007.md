## Design and invariants

Retain existing shared SHA-256 exact-name identifier, including empty actual map member, with absent identifier for missing member or placeholder. Selector identity and response identity must agree for the same exact name without exposing credentials, URL, driver, results or SQL in identifier. The response header is explicitly authorized; no new history endpoint. The request's response identity determines recording; lost/unidentifiable responses may be omitted, never guessed or retried. The selector determines displayed history. Store only SQL and timestamp; literal rendering, no SQL execution by history actions; keep current control, theme, accessibility and failure behavior. Preserve existing selector values and URL-based switching; duplicate URL ambiguity is pre-existing. Cross-tab simultaneous writes are non-atomic and a pending request can add after clear, neither is hidden. Timestamp monotonic adjustment can be up to 1 ms per closely spaced submission beyond wall clock: inspect that displayed dates remain readable and ordering is correct; do not require timestamp rewrite absent actual failure.

Server digest is preferable to selected text, URL keys or Web Crypto: exact accepted names share one source, no metadata leakage and no secure-context dependency. Do not add abstractions, dependencies, endpoints or storage schema. Broad selector changes, SQL retry, new public contract or uncertain preservation of existing values require Council replan.
