## Design and contracts
Use a versioned SHA-256 of the exact UTF-8 session connection name, rendered as 64 lowercase hex characters. Compute on server with standard Go crypto and in client using a small synchronous pure-JS implementation with standard UTF-8 encoding; no `crypto.subtle`, secure-context assumption, CDN, or added dependency. Verify server/client against shared published SHA-256 vectors, Unicode names and each other. This pseudonym is non-secret, not encryption, and may expose guessable names; do not hash URL, driver or results. Existing name reuse shares history as it shares session identity. Do not log SQL or connection metadata.

In `QueryCurrent`, resolve connection name, URL and driver once from the same decoded request-session snapshot, and preserve current execution/error behavior. Only when the current name is a nonempty valid map member, set `X-Query-History-Connection: <64 lowercase hex>` before any response body, including empty-query and SQL-error HTML. No header if no valid identity, malformed session or missing member. Header is additive: status, body, content type, existing request parameters, execution count and routing unchanged; no session mutation, endpoint, new cookie, or data sent to server. Test invalid session and actual SQLite error/success locally with synthetic fixtures; Go handler tests without live DB must ensure digest exactly corresponds to the connection used for execution. Do not change other callers of `getConnection` or their behavior; introduce a narrowly scoped resolver if needed and preserve preexisting missing/malformed lookup behavior. The header contains no name, credentials, URL, driver, SQL or results. Same-origin HTMX can read it under HTTP and HTTPS.

At HTMX request start capture exact submitted `sql`, timestamp and request identity keyed by the actual XHR, only for real query POST initiators. On response completion, including HTTP/SQL errors with an accessible valid header, append once using that XHR's header, not selector or completion order; ignore invalid/missing header, network loss, timeout and abort, clean transient state, never retry or infer from another response. On early failure without a reliable XHR/header, omission is authorized. Preserve query submission even if history code throws. Correctly match out-of-order responses independently. Use request timestamp and a stable per-submission in-memory tie-break for newest order within a tab; preserve duplicates and sort before trimming to 50 even when responses return out of order. On reload ties may retain existing array order. A pending response arriving after a delete/clear is a later add, and can reappear; do not resurrect already deleted stored entries from stale snapshots.

Displayed history uses the digest of the currently confirmed selector option's text, not URL-bearing value. Initial load/selector replacement recompute from selected text, treating placeholder and nonexistent/missing current as unavailable. During an in-flight selection change hide history or show unavailable until returned selector confirms; queries continue normally and their response identifiers determine attribution. Stale selection changes, failures, duplicate URL responses, creation and overlapping swaps must never redirect a stored entry: recompute display from the selector actually present after each swap, and render asynchronous results only if display generation and identifier still match. Another tab may change the shared cookie while this tab's displayed selector remains stale: show history corresponding to this displayed selector, but record each query under response ID; refresh on selector swap and `storage` events, never silently relabel query. If selector shows an apparently valid name absent from session map, history display is harmless but query without valid header is not recorded. No network request solely to synchronize selection.

Persist versioned namespaced key per digest with JSON array of `{sql,timestamp}` only, validating entries, dates and array shape and bounding it. Serialize local operations in a tab and always reread before mutation. On another tab's storage event refresh visible list without applying stale rendering. localStorage has no cross-tab atomic read-modify-write: simultaneous tabs may lose additions/deletions or a clear, though every successfully written array remains capped and isolated; tests must demonstrate this limitation without claiming lossless coordination. No cross-connection mutation or unrelated key deletion. No extra timestamp/index/lock metadata containing connection data. Guard storage getter/get/set/remove, JSON and theme initialization and toggling: failure must not cancel query, and history may show unavailable. Invalid JSON/entries cannot break page; avoid deleting unrelated keys.

Render SQL with `textContent`, no HTML interpolation, plus readable time, accessible full text and load/remove buttons. Notice that browser stores potentially sensitive SQL. History actions must not trigger delayed Auto-Run: suppress only the already scheduled auto input at `htmx:beforeRequest`, with editor/generation marker invalidated by subsequent genuine input; do not dispatch input on load or cancel manual and tree-generated requests. Real HTMX tests must validate; if its actual event behavior requires a materially different query-control design, replan rather than silently weaken. In-flight already sent query cannot be undone. Panel remains outside `#query-main`, accessible names, keyboard and visible focus, both themes and 320px layout.

Alternatives: Web Crypto alone fails supported remote HTTP; hashing URL violates privacy; deriving request identity from selector misattributes shared-cookie/switch races; suspending recording during switch loses valid submissions; server-side history/new endpoint is unauthorized. Deterministic digest is guessable but meets non-secret identifier constraint without adding persistence or dependencies.
